# Cycle QA round — 2026-10-19

Full round on the live cycle (all four switches on), two days after launch. Three sources:

1. **Production data** (read-only SQL on the live DB, ~11:00–15:00 Amman).
2. **Code audit** of five areas: suggestions & credits, after the match (intro / chat / safety), notifications & daily job, account & security, member UI & copy.
3. **Local end-to-end run** (Playwright, phone viewport) with the local test accounts: decide / undo / «لا» secrecy, mixed match, guardian share, chat filter, rate limit, double tap, block / report / unblock, «لم يحصل نصيب», «تمت الخطبة», pause / return, page smoke test.

New gaps are registered as **G53–G68** in `docs/platform-flow.html`. Items marked *verified live* were reproduced in the local run or seen in production data; the rest were verified by reading the code end to end.

## Health check — what is fine

- Production data is consistent: no ACCEPTED row without a match, no PENDING row with a «لا», no overdue card, refunds only where one side never answered, ledger = balance for every post-launch member, no same-gender row, test group isolated since launch, daily job runs in ~10 s with 0 errors.
- Verified live: «لا» + 5-second undo; a «لا» leaves no trace on the other side (feed, waiting tab, notifications); deciding a closed card → 404; a double «مهتم» charges once; mixed match (chat + family) opens as designed and neither guardian shows until both shared; sharing twice is harmless; every by-id route refuses another member's match / chat / photos (404 / 403); chat filter blocks Latin and Arabic digits, spaced / dashed digits, «واتس», handles, domains, "at gmail dot com"; 5-per-5-s limit; extension refused before the last 3 days; read receipts; block → chat ENDED, blocked person keeps it read-only and can still report, send → 404, unblock keeps the chat ended; «لم يحصل نصيب» hides guardian contacts for both; pause → every API 403 `DEACTIVATED`, return works; notifications / payments / referral / support / edit / blocks pages load.
